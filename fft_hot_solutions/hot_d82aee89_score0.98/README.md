### Reconstruction caveats (honest)

- The merge's collision-rename step probes duplicate symbols with
  `gcc -fsyntax-only -march=native`; off-host this was replayed with an
  Apple-clang cross-target shim (`dev_generators/replay/gcc-shim/`,
  `-target x86_64-unknown-linux-gnu -march=icelake-server` + stub libc headers).
  It converged in one iteration, renaming 7 ids (`big_alloc` in f30; `VHALF_`,
  `VONE_`, `alloc_huge`, `alloc_huge_st`, `map2`, `stagger_ctr` in b00) — all
  consistent with the engine sources — but a different compiler's error set
  could in principle differ from the container's gcc. The final file passes the
  same cross-target syntax check.
- Generator-baked twiddles: in-container the generators ran with x86 80-bit
  `np.longdouble`; this host's `longdouble` is 64-bit. For b00 the attempt's own
  in-container regeneration was logged byte-stable against the identical repo
  file used here, which bounds the risk for the other generated parts; last-ulp
  constant drift in s81/d43 cannot be fully excluded.
- Functional verification (correctness gates, timing) is impossible on this
  arm64 machine — the file was verified structurally (part order, pragma fences,
  dispatch content, 3.3 MB size matching the attempt's own final summary, and
  the log's in-container `cmp /workdir/implementation.c /tmp/w/regen/merged.c`).
- The container's final `dev/gen/gensoadrv.py` had been clobbered by an
  abandoned rewrite AFTER `implsoa.c` was emitted; `dev_generators/gensoadrv.py`
  preserves that final (broken) state, while `emitted/implsoa.c` was produced
  from the pre-clobber state exactly as in the container.

## Approach (what this attempt did beyond the round-2 frontier)

The attempt spent its first hours re-measuring the machine from scratch with
inline-asm rdtsc probes rather than trusting the prior notes: zmm FMA sustains
2.0/tsc-tick, loads co-issue free only up to 1 load per 2 FMAs, streaming
stores cap near 0.5/tsc, vdivpd/vsqrtpd cost ~45 tsc in FMA mixes, and the
z/(1+|z|) map floors at ~15.3 tsc per 8 sites regardless of formulation. It
then built two genuinely new generator-emitted engine families — SoA-8
one-sweep-per-step engines for L=6–23 with folded symmetric prime codelets
(cos/sin phase-split, scratch-based in-place safety, loop-inside-function
constant hoisting) and within-volume one-sweep engines for 36/45/64 (PFA 4×9 /
9×5, CT 8×8 with the map fused into the completing pass's output stage) — all
correct on first or second compile, but every one measured at or behind the
best prior engine at its size, confirming the prior engines sit on the
structural issue-slot bounds. The shipped solution is therefore a measured
recombination: the four best prior engines regenerated on-host, merged into one
translation unit, and routed per (L,B) with a new remainder-splitting dispatch
at L=13. The genuinely new wins are integration-level: discovering that the
global `-fschedule-insns -fsched-pressure` flags that help b00's small-size
engines by ~6–8% simultaneously wreck s81's 36/45 engines by 30–40% (fixed with
a per-region `#pragma GCC optimize` wrap and no global scheduler flags), and
that TU layout/order cost ~18% at 3×-grading scale (fixed by reordering s81
first and dropping the unused own engines from the merge). Rejected after
honest measurement: two L=64 one-sweep fusions of f30, stage-A prefetching,
SoA-36, padded-XS 6/8 engines, and parallel-seed map variants. Final logged
self-benchmark: 1.16–1.19 s on its calibrated "W1" workload guess vs 4.2–4.4 s
for the local MKL proxy (r ≈ 0.27 on that mix), bitwise-deterministic across
15+ fresh-process shots; the grader measured 1.224 s vs 13.088 s SOTA
(r = 0.0935 → score 0.985).
