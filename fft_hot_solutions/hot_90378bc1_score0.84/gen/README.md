# Generator provenance

`implementation.c` is a merged single-file build of three engines:

1. **Section 1 — vendored engine A**: the complete `implementation_final.c` of
   prior-work attempt `warm_00291a90` (itself generated by its
   `dev_generators_final/build_full.py`, regenerated byte-stable on this host).
   Used for L = 6, 8, 13, 17, 23, 45 (SoA batch-lane PFA/radix codelets for
   6/8, hand-scheduled symmetric prime kernels for 13/17/23, within-volume
   two-stage PFA(5x9) for 45).
2. **Section 2 — vendored engine B**: `impl_3f30.c` (prior-work v6_3f30d81f),
   used for L = 64 (in-place slab/pencil sweeps, digit-transposed 8x8 register
   tiles). Compiled here with -DMAP_STYLE=0 (rsqrt14+NR map; avoids the
   serializing hardware sqrt measured on this VM).
3. **Section 3 — this round's engine** (`gen_fg.py` -> prefixed `MJ_`):
   6D-PFA "digit state" engine for L = 36 (also emits 45, unrouted): state kept
   as a 9^3x(4^3) digit grid per volume, L2-resident across ALL m steps;
   phase A = three DFT9 passes (pure vertical SIMD, zero shuffles,
   4K-alias-skewed row stride); phase B = in-register DFT4^3 per row
   (vertical u3, lane-pair-trick u2, one 8x8 transpose, vertical u1) fused
   with c-add + z/(1+|z|) map (rsqrt14/rcp14 + Newton, scale-carried NR form).
   CRT digit relabeling is baked into codelet output positions; x0/c/output
   permutations are applied once per volume via index tables.

Regenerate section 3: `python3 gen_fg.py` (writes impl_fg.c); merge:
`python3 merge.py` (expects the vendored sections; see merge.py paths).
Routing lives in solution.py `_dispatch`.
